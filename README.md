# Coverage-aware baselines

An early-stage Python reference library for coverage-certified historical
baselines in SQLite. Runs offline with the Python standard library; no pip
packages, network clients, market-data SDKs, models or order execution.

## Quick start

Python 3.10+ is required. Tested on Python 3.12.14 with SQLite 3.53.1.

```sh
python3 -m unittest discover -s tests -v
python3 demo.py
```

The synthetic demo builds an in-memory database with 60 invented observations
for SYNTH_ORBIT. Every fifth observation is a certified zero. All dates, symbols
and values are generated; none are anonymized or sampled market data.
`fixtures/synthetic.sql` is a portable SQLite fixture, generated by:

```sh
python3 synthetic.py > fixtures/synthetic.sql
```

## API and assumptions

```python
from baseline import calculate_baseline

# conn must use sqlite3.Row as its row_factory and the supplied schema.
result = calculate_baseline(
    conn, "SYNTH_ORBIT", "total_premium", 450,
    "2040-03-01", provider="synthetic_alpha",
)
```

`fixtures/schema.sql` defines the minimal schema. The baseline engine only reads
the supplied SQLite connection. Both coverage and events are filtered by the
same explicit provider and symbol.

Only distinct observation dates with at least one `complete` coverage attempt
qualify. This is an **any-complete policy**: later failed or incomplete attempts
do not revoke an earlier complete attempt. Repeated attempts count a date once.
Complete dates without events contribute zero. Missing coverage, unknown,
incomplete and failed dates are excluded, never interpreted as zero.

Coverage certification is a caller-supplied assertion, not independently proven
by this library. The caller must ensure coverage accurately describes the event
scope, deduplicate events, supply valid canonical YYYY-MM-DD dates and finite
numeric inputs, and interpret evaluation dates consistently. The fixture schema
uses unique event IDs. Malformed-input hardening is not comprehensive.

The evaluation date and future dates are excluded. Observation dates are **not
verified exchange sessions**; the synthetic fixtures intentionally include
weekends. No exchange calendar is included.

## Statistics

Supported metrics: event count, total premium, call premium, put premium, total
volume and maximum event premium. Percentiles use empirical mid-rank ties.
Relative change against a zero median is undefined and returned as null.

- Fewer than 10 observations: insufficient history, no window statistics.
- 10–19: provisional statistics over all observations, no rarity label.
- 20–59: statistics over the latest 20 observations.
- 60 or more: statistics over the latest 20 and latest 60 observations.

Legacy `20D` and `60D` status labels mean observation counts here, not calendar
days or verified trading sessions. Rarity labels are descriptive heuristics, not
validated predictions. This reference is for research and software illustration;
it is not investment advice or a trading system.

## Tests and scope

Independent tests cover certified zeros, excluded unknown/incomplete/failed
observations, duplicate attempts, provider/symbol isolation, same-day/future
exclusion, percentile ties, zero medians, maturity boundaries and fixture
reproducibility. No external services or real market data are required.

The statistical core was extracted and adapted from the author's own prior
work. Provider scoping is explicit in both coverage and event aggregation.
Fixtures, schema, demo and independent tests were written for this reference.
No third-party application code or runtime binaries are bundled. Python and
SQLite retain their own upstream licensing terms.
